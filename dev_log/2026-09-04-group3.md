## Post-Acceptance Source Review Fix — G3-Fix｜限价单与资金一致性

### Scope

- 仅修复 G3 Paper Spot 的 Limit Order lifecycle、Reservation、Capacity / Equity 与 Basic Reconciliation；不进入 G4 / G5，不变更任何 Live、Scanner、Strategy、Dashboard、Contract、Short 或 Leverage 行为。

### Implementation

- 新增 `process_open_orders(run_mode, bbo)`：仅以数据库 `OPEN` 状态为最终事实，在同一 PostgreSQL transaction 内完成符合 BBO 条件的 All-or-None Limit Fill；BUY 使用 `Best Ask <= Limit Price`，SELL 使用 `Best Bid >= Limit Price`，成交价为当前可执行 BBO 且不会劣于限价。
- Limit BUY 冻结 `Limit Notional + Fee`；Fill 或 Cancel 在同一 transaction 内释放 `reserved_cash`。Limit SELL 使用并清除 Order `reserved_quantity`；新 SELL 会扣除同标的已有 OPEN SELL reservation，防止超卖。
- 新增幂等 `cancel_order(order_id)`；只有 `OPEN` 可取消，已取消或已成交订单不可回退。
- Capacity Check 现在纳入同标的 OPEN BUY pending exposure；执行时权益为 Cash 加全部持仓的 Fresh BBO mark，任一核心持仓缺少可靠 Fresh Mark 即 Fail Closed。
- Basic Reconciliation 扩展为：OPEN BUY Reserved Cash、OPEN SELL Reservation 与 Position、Net Fill Position Quantity、Available Cash、Fill-to-Ledger 以及 FILLED Order-to-Fill，并返回明确 diagnostics；不实现 SAFE_MODE 或修复动作。
- 现有 Schema 已具备必要字段，未新增 migration。

## Post-Acceptance Source Review Fix 2 — Limit Fill Stale Guard

### Scope

- 仅补齐 OPEN Limit Order 在真正 Fill 前的 Plan / State / BUY entry validity guard；不进入 G4，不实现 SAFE_MODE、Emergency Stop 或 Plan Cancel Runtime。

### Implementation

- `process_open_orders()` 的每个候选订单在持有 Order Row Lock 的 Settlement transaction 内，按 `order.plan_id` 重新读取并 `FOR UPDATE` 锁定 `TradePlanRecord`。
- Fill-Time 必须验证 Plan 存在、run mode 与 instrument 一致、`ACTIVE`、未过期，以及 `state_version_for()` 等于持久化 Plan state version。
